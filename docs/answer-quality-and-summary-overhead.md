Continuation does not prove factual correctness, pool token caps or bypass provider quotas. It is not token streaming and does not force short answers into multiple sections.

Commands, case insensitive, in either console or browser chat:

- CONTINUE (or CONTINUE ANSWER, RESUME ANSWER, /continue): resume the next unfinished section of the saved text answer.
- FULL ANSWER (or SHOW FULL ANSWER, CONSOLIDATE ANSWER): locally assemble completed sections in original order; when still pending, clearly label the result partial.
- CANCEL ANSWER: discard that chat's continuation; previously archived messages remain.

The database is outputs/memory/answer_continuations.sqlite3, keyed by the existing scoped chat thread identity. Named chats, users and memory spaces remain isolated. The saved ledger contains the original text context, outline, contiguous completed section IDs, covered points, completion state and a publication cursor. Continue does not re-plan, regenerate previously completed sections, read project files, search sources or replay/approve actions. Every pass retains existing model-call/input/output/size bounds and honors the selected provider order. An already complete answer returns a local acknowledgement; it makes no extra model request. A subsequent ordinary message supersedes the old continuation, while the published logical answer remains available as previous_exchange context for that immediate follow-up. Using another chat preserves the first chat's progress.

Published sections and newly generated sections are tracked separately. This allows recovery of a committed but not-yet-published prefix after an interrupted generation, and normal resumes return only unpublished sections. FULL ANSWER remains available for a consolidated view. A candidate section whose progress write fails is withheld, so the next retry does not skip it. Existing transcript/checkpoint save-failure notices remain; exact-once delivery to a browser across a failure between the last database write and client rendering is not guaranteed. These text controls never grant action permissions. Bare continue without a saved text answer retains existing workflow handling; explicit text controls with no saved answer stay local.
